# Stage 23: lower encoder learning rate

Prospective protocol, 2026-11-09. This experiment is authorized by the user. Existing stages remain read-only.

- A: pinned NVIDIA MambaVision-S-1K completely frozen, historical 64-channel adapter and Swin pixel decoder.
- B: identical initialization, stem and levels 0/1 frozen; only levels 2/3 and the same adapter/decoder trainable. No new modules, loss terms, scan changes, or extra data.
- Both encoder paths stay in eval mode. This intentionally fixes BatchNorm buffers and stochastic-layer behavior while allowing gradients in B's last two levels. Eval mode is not no_grad. This isolates weight adaptation; it is not a claim that this training policy is optimal.
- Load exact HF revision e4f9ea93877fba6f1e2d231fd0f0a391368ad895; require strict state loading and recorded pretrained SHA256. Preserve the official unused classification head frozen.
- Source data: original 1886 train / 808 development validation, every image and mask verified against the archived stage1 manifest. Before formal training, perceptual/structural/SIFT screening and paired-image review found same-photo/color/related-view leakage that exact file/pixel hashes missed. Preserve prior smoke outputs as engineering checks, never as clean benchmark results.
- Active partition: identity_partition.json fixes 1886 training / 762 development validation / 867 filtered official test images. Preserve all original training samples. Remove reviewed image groups from validation when also in training, use one eligible validation/test image per reviewed group, exclude test groups represented in any legacy development data, and quarantine explicitly uncertain holdout views. The JSON records every exclusion and audit hashes. Both arms use this identical partition; scores are not directly comparable to the old 808-image validation. Screening is not proof of absence of every duplicate or patient independence. Within-training repeated views remain and are not independent subjects.
- Test plan: test_protocol.json retains the 1000 originally nominated official candidate IDs; identity_partition.json specifies the actual eligible 867-image subset after outcome-blind audit. The training pipeline never reads test images/masks or computes test scores. After model/hyperparameter choices are locked, test only the checkpoint selected by validation macro Dice. Report this as a filtered official test subset, not the full official benchmark. Existing development validation cannot be relabeled as an independent test.
- 256x256; historical PIL resize, normalization, image/mask augmentation and loss. Seed 42. Epoch augmentation is fixed independently of batching by 42+epoch*100003. No preprocessing changes.
- 300 epochs, effective batch 64, 30 updates per epoch with the tail retained. Gradients from microbatches are weighted by actual sample count. GPU calibration chooses the largest safe microbatch among 64/48/32/24/16/8/4; both arms use the same value. GPU cache is limited to input data, frozen-prefix features and A's frozen features. B's trainable-stage outputs are always recomputed, including every validation epoch.
- AdamW, weight decay .01, betas (.9,.999), eps 1e-8; adapter/decoder initial LR .001, B encoder LR .00003. Cosine multiplier over 300 epochs ending at .01 of each group's initial LR. No warmup and no early stopping. Clip decoder and encoder groups separately at norm 1 so B's encoder gradients do not alter decoder clipping policy in A versus B.
- BF16 autocast, FP32 parameters/loss/optimizer. Same initial decoder state, same images and augmentation in each arm. Frozen-feature caching is checked against the official complete feature path.
- Require torch.use_deterministic_algorithms(True), cuDNN deterministic mode and CUBLAS_WORKSPACE_CONFIG=:4096:8. Preserve initial failed smoke attempts and diagnostics. The frozen arm repeats exactly with these settings. An isolated fixed-input selective_scan_fn backward test still shows non-bitwise-repeatable gradients in the installed external CUDA extension; PyTorch's deterministic flag does not make that extension deterministic. Therefore checkpoint model/optimizer/RNG restoration, next forward loss, decoder update and frozen tensors must match exactly. For B's trainable encoder, require replay discrepancy <=1% of the update L2 norm and <=1e-4 maximum absolute parameter difference, and record measured discrepancies. This tests recovery within measured numerical repeatability, not bitwise-identical future trajectories or cross-hardware reproducibility.
- Select maximum validation macro Dice, earliest exact tie. Also retain minimum validation loss and epoch-300 checkpoints. No retrospective selection of different criteria per arm.
- Smoke: two full epochs with independent outputs, interruption/resume consistency, finite gradient checks, frozen-state hashes, trainable parameter changes, official/cached forward equivalence, and memory calibration. Smoke weights never initialize formal runs.
- Formal evaluation: common evaluation.py macro/pooled Dice, IoU, precision/recall, Prec@.5-.9, threshold Jaccard; original stage1 boundary F1, HD95 pixels/diagonal, per-image records, paired error counts and exploratory image bootstrap. Preserve predictions for best Dice. Training seed variability is not estimated by image bootstrap.
- Save recoverable latest state atomically every epoch, including model/optimizer/RNG, source hashes, data identity, progress and learning rates. Export source/environment/data/capacity audits. Count all encoder parameters and complete-system inference costs.
- If a gradient, data or recovery check fails, stop before formal training; numerical failure during training produces a failed status, not silent hyperparameter changes. This stage tests a training policy, not a novel segmentation algorithm.

- Prospective follow-up: compare B at encoder LR 3e-5 with completed stage22 B at 1e-4. Decoder LR remains 1e-3. Repeat the frozen A control to audit the unchanged trajectory. Same seed42, paired augmentation, split, initialization, 300 epochs and selection criterion. No new module, loss or seed change. The intervention is encoder learning rate only.
- Decision based on completed stage22 results (DECISION.json): early best validation Dice and rising validation loss despite falling training loss suggest testing adaptation strength before adding capacity. This is an exploratory development experiment, not proof that learning rate caused overfitting. Seed confirmation follows recipe selection; test remains held out.

- Pre-formal numerical-check correction: the first smoke attempted a tighter 3e-5 absolute replay bound than stage22 and observed 3.0279159545898438e-5 maximum discrepancy, with 0.000998178840073136 relative-to-update L2 discrepancy. Model/optimizer/RNG restoration and forward loss were exact. Keep the failed attempt; return to the unchanged stage22 recovery limits (1e-4 absolute and 1% relative-to-update L2) so only the training learning rate differs. No formal epoch was run under the rejected smoke.
