# LocalContour Phase 2：候选充分性与全局轮廓修补验证

> **2026-10-06 审计更正：本阶段训练标签存在严重索引错误。以下 B/C 阶段模型比较与停止全局方向的结论均暂缓使用；数值仅保留作错误发现前的历史记录。见 [审计错误通知](AUDIT_NOTICE_2026-10-06.md)。当前状态：`BLOCKED_IMPLEMENTATION_REPAIR_AND_RETRAIN`。**

本阶段按 `protocols/LocalContour_下一阶段实验计划_2026-10-05.txt` 先做候选诊断，再做强局部模型与 DP，最后比较相同参数量、相同训练预算的局部、中程和全局 Transformer。**结论：当前实现不支持将“全局 Transformer 轮廓修补”作为主方法。**它相对原 CNN 有很小的开发集增益，但没有超过局部注意力或参数量相近的局部 CNN。官方 ISIC2017 test 600 张始终未用于本阶段评分。

## 数据与复现边界

- 官方 ISIC2017 Task 1：train 2000、val 150、test 600，完整 ID 在 `splits/`；本阶段只读取 train/val 的图像与 GT。历史第一阶段已经查看过 val150，因此这里的 cal50/val100 均是**重复使用的开发数据**，配对区间不能当作独立测试证据。
- 冻结的 [MSGU-Net 作者仓库](https://github.com/A1maan/msgu-net) CNN 使用官方 train+val 混合后重新划分 70/30；其验证集暴露情况记录在 `protocols/split_provenance.json`。CNN 权重 SHA256 为 `3a7fb064383cc68faf33b76561379b69a84141cf51e94679dc31e3a3e66a515d`。本阶段的修补器只用官方 train 训练，val 用于选择模型、DP 参数和保留阈值。
- 旧阶段与本阶段使用同一 CNN 状态哈希。重新推理导致 val150 中 405 个阈值像素与旧缓存不同；本阶段所有方法共享重新推理得到的同一 CNN 基线。细节见 `results/phase2_summary/audit.json`。

## 阶段 A：候选筛选是明显瓶颈

固定 256 个节点、±16 像素，在 val150 的有效单次 GT 交点节点上：

| 候选规则 | 候选覆盖率 | GT 辅助 Oracle Dice |
|---|---:|---:|
| 旧版 0 位 + 最多 3 个峰 | 62.43% | 0.87319 |
| 修正 0 位名额，3 个非零峰 | 62.53% | 0.87326 |
| 4 个非零峰 | 63.08% | 0.87712 |
| 8/16 个非零峰 | 63.34% | 0.87940 |
| ±16 全部整数偏移 | 100.00%* | 0.93764 |

`*` 100% 只针对 32,733 个“法线与 GT 在带内恰好相交一次”的节点；它是稠密整数网格与 2 像素容差的条件性结果。全部计划节点有 38,400 个。扩到 ±32 后，GT 边界落入搜索带的图像平均比例由 88.37% 提到 93.72%，但有效单交点节点由 32,733 降为 30,776，表示更多交点歧义。阶段 B/C 固定 ±32、65 个整数偏移；对应 GT 辅助 Oracle 在 val150 上为 0.95119 Dice，在旧 val100 上为 0.95891。Oracle 在选择时使用 GT，**不能作为可部署效果或 Transformer 可达上界**。

完整逐图诊断在 `results/candidates/`。旧版 G4 的 150 张复算 Dice 与第一阶段逐图完全一致。

## 阶段 B/C：三种子开发集结果

局部模型读取冻结 CNN 的 decoder 特征、RGB、CNN 概率、边界概率及候选位置，新增网络在这些特征上只使用 9×9 窗口。标准版 137,217 参数；局部大模型 291,841 参数；各注意力模型均为 2 层、128 维、4 头、287,425 参数。每组训练 8 epoch，种子 17/23/42。CNN 特征本身可能包含远处图像信息，所以注意力消融隔离的是**新增的跨轮廓节点通信**，不能声称局部组只见原图局部像素。

下表是每个模型在 cal50 选择位移惩罚后，对旧 val100 的三种子平均；Boundary F1 容差为输入 256×256 坐标的 2 像素，HD95 越低越好。

| 方法 | Dice | Boundary F1 | HD95 |
|---|---:|---:|---:|
| 冻结 CNN | 0.85305 | 0.51378 | 16.178 |
| 强局部小模型 | 0.85312 | 0.53284 | 16.254 |
| **参数匹配局部大模型** | **0.85564** | **0.54490** | **16.123** |
| 局部注意力 ±8 | 0.85393 | 0.52162 | 16.169 |
| 中程注意力 ±32 | 0.85362 | 0.52012 | 16.176 |
| 全局注意力 | 0.85360 | 0.51967 | 16.184 |

全局相对局部注意力 Dice 为 −0.00033，逐图配对 bootstrap 95% 区间 [−0.00060, −0.00008]；相对局部大模型为 −0.00203，区间 [−0.00555, 0.00099]。全局相对 CNN 为 +0.00055，但没有满足优于两个强局部对照、多个种子稳定获益以及 HD95 同步改善的计划标准。逐图、逐种子、配对结果在 `results/phase2_summary/`。

单独按最高候选分数移动会严重过度修补。闭环 DP 在 val150 重新选择参数后，三种子平均 Dice：局部小模型 0.84093、局部大模型 0.84414、全局 Transformer 0.83924；这一组 **在 val150 上选择并报告参数**，只能作为开发对照。显式 keep/repair 门控采用相同局部/全局结构训练；扩展校准阈值的过程在 `protocols/gate_threshold_extension.json`。三个种子都选择 0.95，最终没有移动任何节点，故没有形成有效的全局修补。

五类病例按固定条件统计为 A=14、B=0、C=3、D=30、E=2。B 类要求“全局比原 CNN 和局部大模型都至少提高 0.005 Dice”；没有满足条件的病例。`results/phase2_summary/case_panels/` 只展示真实存在的病例，图中绿色为 GT 边界，青色为 CNN，紫色为局部大模型，红色为全局模型。

## 判定与可复现文件

`results/phase2_summary/summary.json` 给出 **STOP_GLOBAL_PRIMARY_AFTER_DEVELOPMENT**：当前结果支持继续研究候选生成与局部修补，但不支持把全局 Transformer 作为论文主张。官方 test 保持封存，留待方法真正达到开发阶段标准后进行一次独立检验。这一结论仅适用于固定 CNN、当前候选标签/模型与训练预算，不否定其他 CNN–Transformer 结构。

`results/training_records/` 保存 21 组训练记录、逐 epoch 曲线、源代码提交和本地 checkpoint 哈希；`results/phase2_summary/audit.json` 为数值与数据审计；`protocols/` 保存方案、初始锁定、错误 GT 缓存的修复记录及后续校准变更。错误标签训练的首轮权重已删除，所有正式模型在完整二维 GT 修复后重新训练。

源码按 GitHub 同仓库相邻的第一阶段目录寻找 `contour/`；也可设置 `LOCALCONTOUR_PHASE1_ROOT`。数据根目录可设置 `ISIC2017_ROOT`。首次运行需按第一阶段代码下载公开 CNN 权重并重新训练边界头，然后运行 `build_feature_cache.py`、`build_candidate_cache.py --radius 32`、`build_node_context.py` 和相应训练脚本。阶段 A 与病例图还需要第一阶段在本地生成的 `results/cases/*.npz`。临时大缓存及逐候选分数可重新生成，本仓库只发布源码、方案、数值结果和少量病例图；**不上传权重或原始数据集**。
