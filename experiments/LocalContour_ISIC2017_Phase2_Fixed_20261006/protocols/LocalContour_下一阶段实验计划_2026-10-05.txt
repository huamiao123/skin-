皮肤病灶分割：CNN候选 + Transformer轮廓修补
下一阶段研究计划与实验协议
日期：2026-10-05

============================================================
一、文档目的
============================================================

本文件用于明确当前“CNN提出局部边界候选，Transformer利用更大范围上下文进行候选消歧和轮廓修补”方向的下一阶段实验计划。

当前实验目录：
experiments/LocalContour_ISIC2017_20261005

当前阶段并未完成“CNN + Transformer修补器”的正式验证，而是完成了候选生成、局部打分、轮廓联合选择以及GT辅助Oracle的前置验证。

因此，下一阶段的核心任务不是单纯追求更高Dice，而是回答以下三个问题：

1. 当前候选生成器是否提供了足够好的搜索空间？
2. 当前错误主要来自“候选没有覆盖正确位置”，还是“正确候选存在但局部模型选错”？
3. 当候选空间与局部基线都足够强后，跨段/全局Transformer是否仍然带来不可被局部模型或简单平滑替代的增益？

只有第三个问题被明确验证，才能把“Transformer负责整体轮廓理解和修补”作为论文的核心方法动机。


============================================================
二、当前实验结果总结
============================================================

当前核心结果如下：

G0：
原始CNN预测。
Dice ≈ 0.853069
Boundary F1 ≈ 0.513837

G1：
不移动候选点，仅执行轮廓候选化与重建。
本质上仍选择偏移0的位置。
Dice ≈ 0.853082
Boundary F1 ≈ 0.513374

G2：
每个轮廓位置独立使用局部评分选择得分最高的候选。
不考虑前后点之间的轮廓一致性。
Dice ≈ 0.841146
Boundary F1 ≈ 0.499581

相对G0：
Dice约下降1.19个百分点。

G3：
在与G2相同候选基础上，通过动态规划联合选择整条闭合轮廓。
加入相邻点平滑与轮廓连续性约束。
Dice ≈ 0.849274
Boundary F1 ≈ 0.508378

相对G2：
有明显恢复。

相对G0：
Dice仍约下降0.38个百分点。

G4：
GT辅助Oracle。
使用真实标注提供与正确边界有关的候选代价，再进行联合选择。
Dice ≈ 0.888135
Boundary F1 ≈ 0.671347

相对G0：
Dice约提升3.51个百分点。

------------------------------------------------------------
当前最重要的结论
------------------------------------------------------------

1. 当前不使用GT的方法还没有超过原CNN。
因此，本方向尚未被正式验证成功。

2. G4显著优于G0。
说明CNN局部边界附近确实存在较大的“可修正空间”。

3. G3优于G2。
说明“独立逐点判断”不是最优策略，轮廓整体一致性具有价值。

4. 但G3仍低于G0。
说明现有局部评分、候选生成、动态规划参数或它们的组合仍然不够好。

5. 目前不能直接把G4和G3之间的差距解释为“Transformer可以填补的空间”。
因为该差距可能同时来自：
   - 候选覆盖不足；
   - 局部评分器太弱；
   - DP参数未充分优化；
   - 特征表达不足；
   - 真正需要长程上下文的歧义。

下一阶段必须逐项排除这些因素。


============================================================
三、研究核心假设
============================================================

假设H1：CNN已经提供了具有较高价值的局部边界先验。

含义：
原CNN不需要被完全替代。
多数区域的边界已经较正确，后续模型应以“局部纠错”为主，而不是重新进行一次完整分割。


假设H2：边界错误可以分为两类。

A类：候选缺失错误
真实边界没有进入当前候选集合。

这种错误无法通过候选选择器解决。
无论Transformer多强，只能从错误候选中选一个相对较好的结果。

B类：候选消歧错误
真实或接近真实的候选已经存在，但局部评分器选错。

这类错误才是Transformer最应该解决的问题。


假设H3：部分候选消歧不能仅靠局部纹理解决。

典型情况包括：
- 毛发、反光、气泡、皮肤纹理导致的局部伪边缘；
- 病灶内部颜色变化产生的假边界；
- 病灶边缘非常模糊；
- 局部梯度存在多个峰；
- 某一点单独看多个候选都合理，但结合整个病灶形状后只有一个合理。

此时需要更长范围上下文。


假设H4：Transformer的价值不应定义为“参数更多”。

如果更强局部CNN/MLP即可达到同样效果，则“Transformer利用全局结构修补”这一核心论点不成立。

因此必须与参数量和训练预算尽可能匹配的强局部基线进行比较。


============================================================
四、下一阶段总体实验路线
============================================================

实验分四个阶段。

阶段A：候选生成器诊断
阶段B：建立强局部基线
阶段C：加入跨段/全局Transformer
阶段D：完整消融与独立测试

必须严格按照这个顺序推进。

原因：
如果阶段A候选空间本身严重不足，直接训练Transformer没有意义。
如果阶段B的强局部模型已经解决大多数错误，则没有必要把改进错误归因于Transformer。


============================================================
五、阶段A：候选生成器诊断
============================================================

目标：
回答“正确边界究竟有多少是因为候选筛选而被提前丢掉的”。

------------------------------------------------------------
A1. 固定搜索半径，改变候选数量
------------------------------------------------------------

保持：
- CNN完全不变；
- 边界节点不变；
- 法线计算方式不变；
- 搜索半径不变；
- 测试集不变。

仅改变每个节点保留的候选数量。

建议：

A1-1：当前方案
0位 + 当前峰值候选。

A1-2：
最多保留8个候选。

A1-3：
最多保留16个候选。

A1-4：
稠密候选。
保留搜索半径内全部整数偏移位置。

如果搜索半径R=16：
候选偏移为
{-16, -15, ..., -1, 0, 1, ..., 15, 16}

目的：
估计峰值筛选本身损失了多少GT可达性。

------------------------------------------------------------
A2. 修复候选名额未补满问题
------------------------------------------------------------

当前候选生成逻辑需要检查以下情况：

若0偏移已经进入前K个峰，
后续写入阶段又跳过0偏移，
则最终非零候选可能少于预期数量。

新版生成器应明确：

1. 0偏移单独保留；
2. 从非零峰值中再选K个；
3. 不允许0偏移占用非零候选名额。

该修改只能用于新实验，不回写旧实验结果。

------------------------------------------------------------
A3. 统计指标
------------------------------------------------------------

至少统计：

1. Search-band coverage
真实边界是否落入搜索带。

2. Candidate coverage
在候选集合中是否存在距离GT足够近的候选。

3. Candidate recall@K
K=1,2,4,8,16等。

4. GT-nearest candidate distance
每个有效节点中，GT到最近候选的距离。

报告：
- Mean
- Median
- P90
- P95

5. 每张图的候选覆盖率分布。

6. 候选覆盖率与最终Dice的相关性。

------------------------------------------------------------
A4. 阶段A判定标准
------------------------------------------------------------

若稠密候选下candidate coverage明显接近上限，
但当前稀疏候选明显较低，
则说明主要问题在候选筛选。

若即使稠密候选仍有大量GT无法覆盖，
说明搜索半径或法线表示本身存在限制。

如果大量严重漏分病灶的真实边界在搜索带之外，
应明确将其归为：
“单步局部边界修补无法解决的结构性错误”。

这类病例不应强行归因于Transformer选择失败。


============================================================
六、阶段B：建立强局部选择基线
============================================================

目标：
回答“当前G2失败是不是因为局部评分器太弱”。

目前局部评分头参数量很小。
因此必须建立比当前版本明显更强的局部模型。

------------------------------------------------------------
B1. Baseline-L0：当前局部评分器
------------------------------------------------------------

保留当前G2。

作用：
历史基线。


------------------------------------------------------------
B2. Baseline-L1：局部MLP/卷积评分器
------------------------------------------------------------

输入建议包括：

1. CNN decoder feature；
2. RGB局部特征；
3. CNN probability/logit；
4. 图像梯度；
5. 候选相对原边界的偏移量；
6. 局部法线方向；
7. 局部曲率；
8. 邻域中CNN置信度变化。

使用一个明显更强、但只允许访问局部窗口的网络进行候选评分。

例如：
局部窗口大小
9×9
17×17
33×33

注意：
该模型不能访问远距离轮廓信息。


------------------------------------------------------------
B3. Baseline-L2：局部CNN Patch分类器
------------------------------------------------------------

对每个候选截取固定patch。

输入：
- RGB patch；
- CNN feature patch；
- CNN mask/logit patch；
- 候选位置编码。

输出：
每个候选成为真实边界的概率。

该模型作为“很强的纯局部模型”。


------------------------------------------------------------
B4. Baseline-L3：局部模型 + DP
------------------------------------------------------------

使用L1或L2的candidate score，
再加入与G3类似的闭环动态规划。

必须重新校准：
- unary score权重；
- smoothness权重；
- displacement penalty；
- curvature penalty（若使用）。

目标：
给“局部判别 + 简单结构约束”一个公平且充分优化的上限。


============================================================
七、阶段C：Transformer跨段候选修补
============================================================

只有当阶段A和B完成后才正式进入。

目标：
验证：
在候选充分、局部基线足够强的条件下，
跨段上下文是否仍然提供稳定增益。


------------------------------------------------------------
C1. 基本输入表示
------------------------------------------------------------

对每个轮廓节点i构建token：

Token_i =
[
局部CNN特征,
RGB局部特征,
CNN概率,
边界置信度,
局部梯度,
法线方向,
曲率,
节点位置编码,
候选特征
]

可以有两种表示。

方案1：Node Token
每个轮廓节点一个token，
token内部包含该节点全部候选的信息。

方案2：Candidate Token
每个候选一个token，
增加：
- node id embedding；
- candidate offset embedding。

优先建议先做方案1，
因为计算量更小、结构更清晰。


------------------------------------------------------------
C2. Transformer的真正任务
------------------------------------------------------------

不是重新预测整张mask。

而是：

输入：
CNN给出的闭合轮廓及局部候选。

输出：
每个轮廓节点应该选择哪个候选，
或者预测连续offset。

建议第一版采用离散候选分类：

对于节点i：

p_i(k) = Transformer选择第k个候选的概率。

这样与当前G2/G3/G4接口完全兼容，
实验解释最清楚。


------------------------------------------------------------
C3. Transformer上下文范围消融
------------------------------------------------------------

这是最关键的消融之一。

必须比较：

T-local：
只能关注附近节点，例如±4或±8个节点。

T-medium：
可关注±16或±32节点。

T-global：
可访问整条闭合轮廓。

如果：

T-global > T-medium > T-local

且差异稳定，
可以直接支持：
长程轮廓上下文具有价值。

如果三者几乎无差别，
则“全局Transformer”的必要性不足。


------------------------------------------------------------
C4. 参数量匹配对照
------------------------------------------------------------

必须避免：
Transformer只是因为参数多而赢。

应增加：

Local-Large：
参数量与Transformer尽可能接近，
但感受野仍限制在局部窗口。

比较：

Local-Large vs Transformer-Global

只有后者仍明显更好，
才能证明优势更可能来自信息范围，而不仅是容量。


------------------------------------------------------------
C5. Transformer + DP
------------------------------------------------------------

可作为后续消融，而不是第一版核心。

比较：

Transformer直接逐点选择；
Transformer输出score + DP联合优化。

如果Transformer本身已经学会轮廓关系，
DP增益可能很小。

这个结果本身也很有价值。

------------------------------------------------------------

------------------------------------------------------------

下一阶段必须重新建立干净协议。

建议：

Train：
仅用于训练CNN和修补器。

Validation：
仅用于：
- 超参数选择；
- 早停；
- 模型选择；
- DP参数调节。

Test：
完全锁定。
方法确定前不得查看。

如果继续使用ISIC2017：

必须明确列出每一张图属于哪个split，
并确保：
CNN训练阶段与修补器测试阶段不存在泄漏。

建议保存：

splits/
    train.txt
    val.txt
    test.txt

并记录图像ID。


------------------------------------------------------------
9.2 CNN处理原则
------------------------------------------------------------

第一阶段建议CNN完全冻结。

理由：
我们的研究问题是：
“在CNN已经给出初始轮廓后，能否通过候选修补提高结果？”

如果同时微调CNN，
就难以判断提升来自CNN本身还是Transformer修补。

等核心结论成立后，
再增加end-to-end fine-tuning实验。


------------------------------------------------------------
9.3 修补器训练标签
------------------------------------------------------------

对于每个边界节点：

找到与GT边界最接近的候选。

可建立：

Hard label：
最近候选为正类。

Soft label：
根据距离GT边界的距离构建概率。

例如：

q(k) ∝ exp(-d_k / τ)

其中：
d_k = candidate k 到GT边界的距离。

Soft label通常比硬标签更稳定，
因为多个候选可能都接近GT。


------------------------------------------------------------
9.4 损失函数
------------------------------------------------------------

第一版建议简单。

L = L_candidate

即候选分类交叉熵或KL损失。

第二版可加入：

L = L_candidate
  + λ1 L_offset
  + λ2 L_smooth
  + λ3 L_keep

其中：

L_offset：
预测offset与GT最佳offset差异。

L_smooth：
相邻节点位移的平滑约束。

L_keep：
若原CNN节点已经足够正确，
鼓励模型保持0偏移，
避免过度修补。

特别强调：
L_keep可能非常重要。

因为我们的任务不是“全部移动”，
而是：
“只修应该修的点”。


============================================================
十、防止过度修补
============================================================

当前方向最大的工程风险之一是：

模型在错误区域可以修正，
但同时把CNN原本正确的区域改坏。

因此应显式研究：

“是否需要修”
+
“怎么修”

可以设计两阶段决策：

Step 1：
预测当前节点是否需要修改。

m_i ∈ {keep, repair}

Step 2：
仅当repair时，
选择候选offset。

也可以设置：
0偏移为一个特殊candidate，
让模型自行选择保持原位置。

必须统计：

1. 原本正确节点中被错误移动的比例；
2. 原本错误节点中被成功修复的比例。

建议定义：

Repair Precision
= 被移动节点中，移动后确实更接近GT的比例。

Repair Recall
= 原本可修正错误节点中，被成功改善的比例。

这两个指标比只看Dice更能解释修补机制。

============================================================
十二、统计与重复实验
============================================================

正式实验至少进行3个随机种子。

推荐5个随机种子。

报告：

mean ± std

主方法与强基线之间增加：

paired bootstrap
或
Wilcoxon signed-rank test

重点不是只证明p-value，
而是同时报告：

- 平均提升；
- 中位数提升；
- 改善病例比例；
- 下降病例比例；
- 置信区间。

必须保留逐图结果CSV。


============================================================
十三、病例分析
============================================================

病例分析至少分为以下五类：

Case A：
CNN已经很好，修补器保持不动。

Case B：
局部模型失败，Transformer成功。

这是最关键病例。

Case C：
局部模型与Transformer都成功。

说明问题不一定需要全局信息。

Case D：
所有模型失败，但Oracle成功。

说明学习器仍有提升空间。

Case E：
Oracle也失败。

说明候选空间本身不够，
不应归因于选择模型。

每类至少保留5~10张代表病例。

============================================================
十五、成功标准
============================================================

这个项目不能以“Transformer比当前G2好”作为成功标准。

最低成功标准应为：

1. Transformer稳定超过原始CNN；
2. Transformer稳定超过强局部模型；
3. Transformer稳定超过强局部模型+DP；
4. 在多个随机种子下成立；
5. Boundary F1/HD95等边界指标同步改善；
6. 改善不是由少数病例贡献；
7. 全局Transformer优于局部注意力版本；
8. 提升可以通过候选消歧机制解释。

理想结果：

CNN
<
Strong Local
<
Strong Local + DP
<
Global Transformer
<
Oracle

============================================================
十六、失败标准与转向条件
============================================================

情况1：
Strong Local已经接近Transformer。

结论：
Transformer并非必要。
应转向：
“学习式边界候选重评分/局部修补”
而不是强调全局Transformer。


情况2：
Oracle提升很小。

结论：
候选接口价值不足。
应重新设计候选生成或放弃该路线。


情况3：
Dense候选Oracle很高，但稀疏候选Oracle明显低。

结论：
重点转向候选生成器。


情况4：
Transformer改善Dice，但Boundary F1/HD95下降。

结论：
可能只是面积偏置，不是真正边界修复。
不得直接宣称轮廓改善。


情况5：
Transformer在已正确区域产生大量错误移动。

结论：
必须引入keep/repair gating或保守正则。


情况6：
Global Transformer不优于Local Transformer。

结论：
“全局轮廓理解”证据不足。
论文叙事必须调整。

============================================================
二十、当前方向的论文级研究问题
============================================================

不建议将论文问题描述为：

“CNN擅长局部，Transformer擅长全局，所以我们把二者结合。”

这种表述过于宽泛，与大量CNN-Transformer融合论文重叠。


更建议定义为：

“CNN分割产生的边界误差中，一部分并不是缺乏局部边缘证据，而是在多个局部合理候选之间存在歧义。我们研究能否将CNN边界预测转化为稀疏候选轮廓，并利用跨轮廓上下文对候选进行结构化消歧，从而只修正不可靠边界，同时保持原本正确的区域。”


对应的核心机制是：

CNN：
生成初始分割与局部边界候选。

Local evidence：
告诉模型每个候选在局部看起来是否合理。

Transformer：
结合远距离边界、病灶整体形状和跨段一致性，
解决局部无法确定的候选选择问题。

Keep/repair机制：
防止对正确CNN边界进行无意义修改。


============================================================
二十一、当前总体判断
============================================================

当前状态：
谨慎乐观。

原因：

积极信号：
1. Oracle相比原CNN约有3.5个Dice百分点的提升空间；
2. G3优于G2，说明结构一致性确实有价值；
3. 当前问题可以被明确拆成“候选覆盖”和“候选消歧”两部分；
4. 有清晰、可证伪的下一阶段实验路径。

风险：
1. 当前非GT方法尚未超过CNN；
2. 候选覆盖仍存在不足；
3. 当前局部基线较弱；
4. 尚未证明全局信息比强局部模型更有价值；
5. Transformer最终可能只能带来很小提升；
6. 严重漏分病例可能超出单步轮廓修补能力。

因此：

现在不应宣布方法成立，
也不应放弃方向。

下一阶段的目标不是“想办法让Transformer赢”，
而是严格判断：

在候选足够充分、局部基线足够强之后，
是否仍然存在一类必须依靠跨段/全局上下文才能解决的边界歧义。

如果答案是“是”，
那么这个方向具备形成核心论文创新点的潜力。

如果答案是“否”，
则应及时转向候选生成、局部修补或其他更符合实验事实的方向。
